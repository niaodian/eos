# ADR-019 — EOS generates each agent platform's configuration from one source, owning entries, not files

- Status: Accepted
- Date: 2026-10-03
- Extends: ADR-017 (skills: one source, generated copies), ADR-018 (the MCP server)
- Depends on: ADR-015 (upgrades are three-way), the shared guardrail rules (`.github/hooks/lib/secret-rules.mjs`)
- Governs: `eos agents sync [--platform …] [--write|--check]`, `agentPlatforms` in `.eos/project.json`,
  `deny-dangerous.js --format`, `.github/eos/lib/agent-platforms.mjs`, the files listed below

## Context

Three open standards carry most of what EOS needs from an agent: `AGENTS.md` for instructions, Agent
Skills (`.agents/skills/`) for the workflows, and MCP for structured tools (`eos mcp`). What is left
differs per platform, and was re-checked against each vendor's documentation on 2026-10-03:

- **MCP configuration**: `.mcp.json` (Claude Code; VS Code reads it directly and calls its own
  `.vscode/mcp.json` deprecated for new servers — that file also stays the Playwright opt-in),
  `.codex/config.toml`, `.cursor/mcp.json`, `.agents/mcp_config.json` (Antigravity), `.gemini/settings.json`.
- **Pre-tool hooks** speak five dialects: `hookSpecificOutput.permissionDecision` (Copilot, Claude Code,
  Codex, Qwen Code), a top-level `decision` (Gemini CLI, Antigravity), `permission` (Cursor),
  `cancel` (Cline), and an exit code (Kiro). Codex gained real hooks; the earlier plan of prefix rules
  is obsolete.
- **Agents**: Copilot reads `.github/agents/` (with handoffs) and `.claude/agents/`; Cursor reads
  `.claude/agents/` and `.codex/agents/`; Antigravity `.agents/agents/`; Codex `.codex/agents/*.toml`.
- **Instructions**: every platform reads `AGENTS.md`, except Gemini CLI until `context.fileName` names it.

These are files a team also edits: `.claude/settings.json` holds their permissions, `.mcp.json`
their other servers.

## Decision

1. **One source per layer.** `AGENTS.md`; `.agents/skills/eos-*`; `.github/agents/eos-*.agent.md`; one
   guardrail program, `.github/hooks/deny-dangerous.js` over `secret-rules.mjs`; `eos mcp`. Everything
   else is generated by `eos agents sync`, and CI fails on drift (`--check`).
2. **Platforms are declared.** `agentPlatforms` chooses them. Absent, the default is Copilot, Claude Code
   and Antigravity — the files in `.agents/`, `.github/`, `.claude/` and `.mcp.json`, which also give
   Codex, Cursor and Gemini CLI the skills and `AGENTS.md`, and Cursor the Claude hook. The rest is
   generated on demand, so a repository is not filled with a dozen dot-directories it does not use.
   `eos agents sync --platform <x> --write` adds one in a single command; because `.eos/project.json` is
   an input of every gate, it says that the recorded evidence needs a re-run.
3. **EOS owns entries, not shared files.** It sets its own entry — the `eos` MCP server, the hook entry
   that runs `deny-dangerous.js`, a marked `[mcp_servers.eos]` block in TOML, Gemini's `AGENTS.md`
   context name — and leaves everything else as it was. Removing a platform removes only its entries,
   and deletes a file only when nothing else is left in it. A file EOS cannot merge safely (JSON with
   comments, an `[mcp_servers.eos]` of the team's own) is reported and nothing is written; nothing is
   written or deleted through a symbolic link. Whole files are written only under EOS's own names
   (`eos-*` agents, the Kiro hook, the Cline script, the OpenCode plugin).
4. **One guardrail, many dialects.** `deny-dangerous.js --format <platform>` reads any platform's payload
   with the same rules and answers in that platform's dialect. It only ever denies: on allow it prints
   no decision, because an explicit "allow" would skip the platform's own approval prompt.
5. **Agents where they do not collide.** Antigravity and Codex get the orchestrators rendered from
   `.github/agents/`. Claude Code does not: VS Code also reads `.claude/agents/`, so every orchestrator
   would be listed twice in Copilot, and Claude Code runs the same workflows as skills.
6. **Tier 2 is generated, and labelled.** Kiro, Qwen Code, Windsurf / Devin Desktop, OpenCode and Cline
   are generated from their vendors' documentation and marked "not yet verified on a real
   installation" in the output and the manual. Cline's MCP entry is not generated: it reads only a
   global file. Trae, CodeBuddy and Comate are not generated: their documentation could not be fetched,
   so they are served by `AGENTS.md` and the CLI until they are verified on a real machine.
7. **Upgrades regenerate.** `eos upgrade` leaves every generated path out of its three-way comparison —
   the template's copies are generated for the template's platforms — and runs the upgraded CLI's
   `agents sync --write` for the project's own.
8. **Trust stays with each platform.** No auto-approve list, no trusted flag, no pre-granted hook: every
   platform's first-use confirmation is kept.

## Consequences

- A team on any Tier-1 platform gets guidance, guardrails and MCP from `degit` + `init`; one command
  adds the others.
- A platform's format change is a change to one table in `agent-platforms.mjs` and its tests, not to
  every repository by hand.
- The generated hooks are speed bumps on a developer's machine, as before; CI stays the authority.
- Tier-2 output can be wrong until someone runs it on the real product. A headless smoke test per
  Tier-1 platform ("what is next?" → asserts the agent called `eos next`) needs vendor accounts and the
  network, so it belongs in an optional manual workflow, not in the offline suite; it is not part of
  this decision.
